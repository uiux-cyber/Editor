# Translating Kinora

Kinora's interface is written in English, and the English text in the code *is* the translation
key. Translations live in JSON files next to the i18n layer:

```
src/renderer/src/ui/i18n/
  index.ts          t(), useT(), setLanguage(), LANGUAGES, Intl formatters
  format.ts         ICU-style message formatting (pure, unit tested)
  locales/es.json   Spanish
  locales/fr.json   French
  locales/de.json   German
  locales/pt-BR.json  Portuguese (Brazil)
  locales/hi.json   Hindi
```

The language is chosen in **Settings → Language** (or *Help → Change language…*). "System
default" follows the Windows display language. Switching is live: no restart, nothing reloads.

## Writing translatable code

```tsx
import { t, useT } from '../i18n';

function SaveButton(): ReactNode {
  const t = useT(); // re-renders this component when the language changes
  return <button>{t('Save')}</button>;
}

toast('success', t('Project saved')); // outside React: the global t()
```

- **Always pass a literal string** as the first argument: `t('Open project…')`, never
  `t(label)` with a variable — the extractor (`scripts/i18n.mjs`) and the tests find strings by
  reading the source. When a string is chosen at runtime (menu names, command titles from other
  files), translate it where it is shown and add it to `EXTRA_KEYS` in `scripts/i18n.mjs`.
- **Never build sentences by concatenation.** Use placeholders so translators can reorder words:
  `t('Save changes to “{name}”?', { name })`.
- **Plurals** use ICU syntax; the right form is chosen with `Intl.PluralRules` for the current
  language (French and Portuguese treat 0 as singular, Hindi has its own rules…):

  ```ts
  t('{count, plural, =0 {No files} one {# file} other {# files}}', { count })
  ```

  `#` is replaced by the formatted number. Also supported: `{n, number}`,
  `{n, number, percent}`, `{d, date, short|medium|long|full}`, `{d, time}`,
  `{kind, select, video {…} other {…}}` and `{n, selectordinal, …}`. Quote literal braces with
  apostrophes: `'{'`.
- **Numbers, sizes and dates**: `formatNumber(n)`, `formatSize(bytes)`, `formatDate(d)` and
  `formatRelative(timestamp)` ("3 minutes ago") from `ui/i18n` use the interface language.
- **Ambiguous words** take a context: `t('Edit', undefined, 'menu')` looks up `menu|Edit` first
  and falls back to `Edit`. Contexts in use: `menu` (title-bar menu names) and `key` (key-cap
  labels such as `key|Ctrl` → `Strg` in German).
- **Commands and settings sections** keep plain English `title` / `group` / `description`
  fields; the palette, menus, settings window and shortcut lists translate them with `t()` when
  they are displayed. Add their translations to the locale files like any other string.
- Content names (templates, effects, stickers, sounds…) are not translated.

Missing translations fall back to English, so untranslated parts of the UI keep working.
`window.__kinora.workflow.i18n.missingTranslations()` lists the strings looked up in the current
session that the active language does not have.

## Adding or updating translations

1. Write the English string in code with `t('…')`.
2. Run `node scripts/i18n.mjs` — it lists, per language, the strings that are missing (and those
   that are no longer used). `node scripts/i18n.mjs --keys` prints every source string.
3. Add the entries to each `locales/<code>.json`: `"English source": "Translation"`. Keep every
   `{placeholder}` and every plural branch; `npm test` fails if a placeholder is missing or a
   string has no translation.

Which files are covered is listed in `TRANSLATED` in `scripts/i18n.mjs` (today: the shell, title
bar, menus, start screen, settings, command palette, keyboard-shortcut dialogs and Collect
project). To move another part of the UI onto the i18n layer, wrap its strings in `t()`, add its
folder to `TRANSLATED`, run the script and fill in the gaps.

## Adding a language

1. Add it to `LANGUAGES` in `ui/i18n/index.ts` (BCP 47 code, native name, English name).
2. Create `locales/<code>.json` with every string reported by `node scripts/i18n.mjs`.
3. If the script needs a font Inter does not cover, add a Windows system font for it to `--font`
   in `styles/base.css` (as `Nirmala UI` is there for Devanagari).

## Style notes for translators

- Match Windows conventions of the language (e.g. Spanish *Archivo / Edición / Ver*, German
  *Datei / Bearbeiten / Ansicht*).
- Keep the trailing ellipsis (…) on commands that open a dialog.
- Use the language's own quotation marks: « » (es, fr), „ “ (de), “ ” (pt-BR, hi).
- Keep product names (Kinora, Windows, YouTube, GPU) unchanged.
